# תסריט תגובה לאירוע אבטחה / פרטיות

טיוטה לפי תקנה 11. **לאישור עורך דין וממונה אבטחה.**

## 1. זיהוי

- התראת cron (`/api/cron/security`): כשלונות login, ייצואי CSV, צפיות בהערות.
- דיווח מדריך / נער / הורה.
- חריגה ב-Vercel / Supabase logs.

## 2. עצירה

- השבתת החשבון החשוד ב-Admin → Users (`disabled` + `signOut` גלובלי).
- ביטול טוקני טפסים (`revoked_at`) אם נחשד קישור קסם.
- סיבוב מפתחות רק אם דלף `SERVICE_ROLE` (תהליך תשתית, לא בקוד).

## 3. היקף

- שאילתה ב-`audit_events` לפי `actor_id` / `action` / חלון זמן.
- רשימת ייצוא CSV וצפיות `view_notes`.

## 4. תיעוד

- מה קרה, מתי, מי, אילו נתונים, אילו פעולות ננקטו.

## 5. הסלמה

- בעל שליטה / DPO / הנהלה.
- דיווח לרשות להגנת הפרטיות אם נעשה שימוש בחלק מהותי מהמאגר בלא הרשאה (סף משפטי — עו"ד).

## 6. שיקום ולקחים

- איפוס סיסמאות / MFA.
- עדכון נוהל והדרכה.
- תרגיל שנתי: "נפרץ חשבון מדריך והורדו הערות על 80 נערים."
